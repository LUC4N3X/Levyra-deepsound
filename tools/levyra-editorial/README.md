# Levyra editorial collector

This tool builds a source-neutral JSON catalog for Levyra from configured public editorial charts.

It runs only in GitHub Actions. The long-lived web session value is stored as an Actions secret and is used only to obtain a short-lived bearer token during the workflow run. Playlist metadata is read through the web player's persisted-query endpoint. The public catalog contains only the metadata Levyra needs: titles, artist names, album names, artwork URLs, durations, release dates, ISRC values when available, explicit flags, and chart positions.

## Security model

- The secret is never stored in the repository, APK, generated catalog, artifacts, or logs.
- Same-repository pull requests can run the live collector with the repository secret; fork and Dependabot pull requests do not receive it.
- The pull-request integration job has read-only repository permissions and never publishes data.
- The scheduled collector fails closed: authentication or complete-catalog failures leave the last published catalog untouched.
- Generated output is scanned for credential-related keys before publication.
- Upstream account, playlist, track, album, artist, URL, cookie, and token identifiers are not published in the application catalog.
- Public track identifiers are generated by Levyra from normalized metadata.
- A dedicated source account should be used. Do not reuse a personal password or session.
- Rotate the secret immediately if a workflow log, local terminal, or third-party service ever receives it.

The source account is not shipped to users. Android consumes only the generated public catalog hosted from the data-only branch.

## Implementation note

The collector is an original Python implementation written for Levyra. The actively maintained SimpMusic project was used as a behavioral reference for the current `sp_dc` plus TOTP web-session flow, including the dedicated server-time endpoint and mobile web-player token profile. No SimpMusic source code was copied into Levyra.

Playlist reads use the web player's `fetchPlaylist` persisted query instead of the developer Web API. The query hash is isolated in one constant and can be overridden without changing code if the upstream service rotates it.

## Repository secret

Create this repository secret:

```text
LEVYRA_EDITORIAL_SP_DC
```

Paste only the value of the `sp_dc` cookie. A complete cookie string containing `sp_dc=...` is also accepted, but the single value is preferable.

GitHub path:

```text
Repository Settings → Secrets and variables → Actions → New repository secret
```

Optional repository variables or workflow environment values:

```text
LEVYRA_EDITORIAL_TOTP_SECRETS_URL
LEVYRA_EDITORIAL_PLAYLIST_QUERY_HASH
```

When omitted, the collector uses the current public versioned TOTP dictionary and the checked-in `fetchPlaylist` query hash configured in `levyra_editorial/spotify.py`.

## Country coverage

`config.json` contains Global plus every Levyra country for which a configured chart is available. `allowPartial` is enabled so one unavailable country cannot invalidate all the others.

The current live run produces 27 collections: Global and 26 country charts. Russia currently returns no usable content page and is skipped. China has no configured source chart. Android keeps both country chips and transparently uses the existing YouTube Music / Apple chart path whenever the public editorial catalog has no matching market.

## Running locally

Never place the secret in a tracked file.

```bash
cd tools/levyra-editorial
python -m venv .venv
. .venv/bin/activate
pip install -e '.[dev]'
export LEVYRA_EDITORIAL_SP_DC='...'
levyra-editorial --config config.json --output ../../build/editorial/catalog.json
levyra-editorial --validate ../../build/editorial/catalog.json
```

## Publishing

`.github/workflows/editorial-catalog.yml` runs:

- unit tests and static checks on pull requests;
- a live read-only collection test on same-repository pull requests;
- collection every six hours and on manual dispatch;
- validation before any publication;
- artifact upload for diagnostics;
- publication of the last valid JSON to the `editorial-data` branch.

Public data URL after the first successful scheduled or manual run:

```text
https://raw.githubusercontent.com/LUC4N3X/Levyra-deepsound/editorial-data/catalog/editorial.json
```

A failed run never overwrites that file.

## Android behavior

Android requests the Levyra catalog first for the selected country. The request is cancellable, time-bounded, cached in memory and on disk, and does not contain the source credential. When a country is missing, the catalog is unavailable, or parsing fails, Levyra immediately keeps its existing YouTube Music and Apple chart fallback.

The application layer resolves playback through Levyra's existing music pipeline; the public catalog supplies ranking and metadata only.

```json
{
  "schemaVersion": 1,
  "generatedAt": "2026-07-29T12:00:00Z",
  "collections": [
    {
      "id": "top-50-it",
      "kind": "chart",
      "market": "IT",
      "title": "Top 50 Italia",
      "description": "...",
      "artworkUrl": "https://...",
      "totalSourceItems": 50,
      "tracks": [
        {
          "position": 1,
          "id": "levyra-...",
          "title": "...",
          "artists": [{"name": "..."}],
          "album": {
            "name": "...",
            "releaseDate": "2026-07-01",
            "artworkUrl": "https://..."
          },
          "durationMs": 185000,
          "explicit": false,
          "isrc": null,
          "artworkUrl": "https://..."
        }
      ]
    }
  ]
}
```

The unit suite asserts that the serialized catalog contains no upstream brand name, URI, external URL, source identifier, cookie, or token material.
